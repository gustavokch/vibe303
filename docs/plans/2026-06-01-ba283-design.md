# BA283 Neural Preamp Emulation — Design Spec

**Date:** 2026-06-01
**Status:** Design approved, ready for implementation planning
**Scope:** Real-time virtual analog emulation of the Neve BA283 mic preamp as a VST3 plugin, using SPICE-derived training data and a small conditioned GRU.

---

## 1. Goals & Non-Goals

### Goals
- Plugin matches a SPICE-rendered BA283 circuit within **−25 dB broadband null** (perceptual transparency, not bit-perfect).
- User-tweakable **bias control** that musically maps to the RV1 wiper position, producing real asymmetric saturation behaviour conditioned into the model.
- **Real-time safe**: zero heap allocation and zero locks in the audio process block. Worst-case callback < 333 µs @ 64-sample buffer / 48 kHz.
- VST3 plugin, dual-mono, host SR-agnostic from 44.1 kHz to 192 kHz.
- Reproducible end-to-end pipeline: a clean checkout regenerates dataset → trained weights → built plugin → green null test.

### Non-Goals
- Bit-exact emulation. Not achievable for a non-linear NN vs SPICE; a hard goal here would set up a false failure.
- Modelling input transformer, hi-Z line, or microphone loading. Single fixed input impedance.
- Modelling the 26 dB gain switch as a user control. Gain bridge (K↔J 220 Ω + 80 µF) is hard-wired in netlist; only RV1 is conditioned.
- aarch64 builds. x86_64-v3 only.
- VST2, AAX, AU. VST3 only for v1.

## 2. Architecture & Data Flow

```
Dry stimulus WAV (96 kHz, 0.5 V peak)
        │
        ├── data_gen/run_spice.py
        │      └── continuous transient sim per (stimulus × bias ∈ {0, .25, .5, .75, 1})
        │             └── data/wet/<stim>_bias<v>.wav  (96 kHz target)
        │
        ▼
train/dataset.py  (manifest-driven, 4096-sample windows, stride 2048)
        │
        ▼
BA283GRU: GRU(input_size=2, hidden=32) → Linear(32, 1)
        │
        ├── train/train.py     (ESR + MSE composite, α=0.85 pre-emphasis, TBPTT 1024/3072)
        ▼
checkpoints/best.pth
        │
        ├── train/export.py    (→ rtneural-rs JSON)
        ▼
weights/ba283_gru32.json  (~30 KB, embedded via include_str!)
        │
        ▼
plugin/  (nih_plug VST3, rtneural-rs ModelT, dual mono, optional 2× OS)
        │
        ▼
tests/verify_*.py  (numerical, bias sweep, latency, realtime)
        │
        ▼
Ableton Live null test ≤ −25 dB → SHIP
```

**Conditioning shape:** the model is **not** SISO. Input is `(audio_sample, bias_scalar)` where `bias_scalar ∈ [0.0, 1.0]` is constant across each training window and across each plugin processing block. The same `bias` value the user sets on the plugin knob is fed as the second GRU input dimension, sample by sample.

## 3. Decisions Locked During Brainstorming

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | **Drive-amount conditioned** (audio + bias scalar) | Gives one meaningful user-facing analog control beyond Drive/Output trim, ~3× dataset vs single snapshot, same model size. |
| 2 | **Train @ 96 kHz, plugin 2× polyphase OS when host < 96 kHz** | Industry-standard (Neural DSP, Wright et al.) — cleaner saturation harmonics without aliasing. |
| 3 | **Null target −20 to −30 dB** | Honest perceptual-match target. The −60 dB number from the original plan is not reachable against SPICE ground truth and would create false failures. |
| 4 | **Engineered (sweeps/chirps/noise) + curated music stimulus** | Wright/Damskagg standard. Synthetic covers full nonlinear state space; music ensures generalization to real source material. |
| 5 | **State-carrying continuous SPICE sim, no chunking** | Eliminates per-chunk DC operating-point re-settle artifacts in training targets. Slightly slower wall-clock per file but correct. |
| 6 | **Plugin params: Drive + Bias + Output + Mix** | Covers conditioned model directly; Mix enables parallel coloration use case with latency-compensated dry path. |
| 7 | **Dual-mono independent stereo** | Standard analog-emulation behaviour, preserves stereo image, ~2× CPU vs sum-and-split, fits CPU budget comfortably. |
| 8 | **Hidden = 32** (vs original 24) | Absorbs extra capacity needed for conditioning input without measurable CPU overhead. |
| 9 | **DataLoader `num_workers=6`** | Per user. |
| 10 | **x86_64-v3 target only** | Per user. |
| 11 | **Output: design doc + per-phase agent prompts**; no code in this pass | Per user. |

## 4. Component Designs

### 4.1 Data generation (`data_gen/`)

#### 4.1.1 Netlist (`netlist.py`)
- `build_netlist(bias_norm: float) -> Circuit` parameterizes RV1 split. Bias maps to wiper position via `R_upper = 4700 * (1 - bias)`, `R_lower = 4700 * bias`.
- Topology: TR1, TR2 = `BC184C`; TR3 = `2N3055` (user-confirmed — flag in code comment that classic BA283 is all-BC184).
- All electrolytics (C7, C4, 80 µF gain cap): cap + 1 Ω ESR series.
- LO1166 output transformer via ngspice XSPICE nonlinear-magnetics code models (two lcouple windings + a core PWL B-H model). The original plan's PSpice-style CORE(MS/A/C/K) + K-line idiom does not exist in ngspice; this is ngspice's genuine nonlinear-transformer path (closest practical equivalent to the Jiles-Atherton hysteresis originally requested).
- Routing: F → LO1166.PRI_IN, PRI_OUT → +24 V rail (A), SEC_OUT → GND, output tap from SEC_IN with 600 Ω termination to ground.

#### 4.1.2 Stimulus library (`stimulus.py`)
- ~20 min total per bias point, 96 kHz, peak 0.5 V.
- **Synthetic (~8 min)**: log sine sweeps 20 Hz → 20 kHz at 4 levels; pink noise bursts; two-tone IMD pairs; impulses + steps; Schroeder-phase multisine.
- **Music (~12 min)**: user-supplied DI bass, DI guitar, dry vocals, drum bus, acoustic guitar, synth. Loaded via `soundfile`, resampled to 96 kHz via `scipy.signal.resample_poly`, peak-normalized.

#### 4.1.3 SPICE execution (`run_spice.py`)
- One continuous transient per `(stimulus_file, bias)` pair. Five bias values: `{0.0, 0.25, 0.5, 0.75, 1.0}`.
- PWL voltage source. Files > 30 s use sidecar `.pwl` to keep netlist compilable.
- Solver: `RELTOL=1e-4`, `ABSTOL=1e-9`, `VNTOL=1e-6`, `GMIN=1e-13`, `METHOD=gear`, `max_step ≈ 1.3 µs` (8× the 96 kHz sample period).
- `.OP` + `.IC` snapshot before transient → skips warmup transient on every run.
- Parallelism: `multiprocessing.Pool(processes=max(1, cpu_count() - 2))`. Per-run stderr logged. Non-convergence → skip + record, do not crash batch.

#### 4.1.4 Resample & manifest (`resample.py`)
- ngspice non-uniform time grid → fixed 96 kHz grid via `scipy.interpolate.PchipInterpolator` (monotonic, no overshoot at clipped edges).
- Trim first 50 ms of every WAV (DC settle margin).
- Manifest CSV: `dry_path, wet_path, bias_value, duration_s, stim_kind`. 80/10/10 split by **stimulus file** (not random windows — prevents musical-phrase leakage across splits).

### 4.2 Training (`train/`)

#### 4.2.1 Dataset (`dataset.py`)
- `BA283Dataset(Dataset)`: yields `(x, y)` per 4096-sample window, stride 2048.
- `x.shape == (4096, 2)`: column 0 = dry audio sample, column 1 = bias scalar broadcast across the window.
- `y.shape == (4096, 1)` = wet target.
- Both pre-scaled by `1/0.5 = 2.0` so model trains in [−1, +1].
- WAV I/O via `soundfile` mmap mode.
- `make_loader(split, batch_size=64)`: `num_workers=6`, `pin_memory=True`, `persistent_workers=True`.

#### 4.2.2 Model (`model.py`)
```python
class BA283GRU(nn.Module):
    def __init__(self, hidden: int = 32):
        super().__init__()
        self.gru = nn.GRU(input_size=2, hidden_size=hidden, num_layers=1, batch_first=True)
        self.dense = nn.Linear(hidden, 1)

    def forward(self, x, h=None):
        y, h = self.gru(x, h)
        return self.dense(y), h
```
- ~3,297 parameters. Fits L1 cache. Sub-1% CPU per channel at 96 kHz on AVX2.
- `state_dict` keys must follow PyTorch defaults — rtneural-rs JSON export depends on it.

#### 4.2.3 Training loop (`train.py`)
- Adam(lr=5e-3) + CosineAnnealingLR. Batch=64. CPU training acceptable.
- **TBPTT**: warm up first 1024 samples per window under `no_grad`, backprop only the last 3072. Prevents gradient explosion.
- **Loss**:
  ```python
  loss = 0.75 * esr(pre_emphasis(pred), pre_emphasis(target)) + 0.25 * F.mse_loss(pred, target)
  ```
  with `pre_emphasis(x, α=0.85) = x[1:] - 0.85 * x[:-1]` (first-order HPF, weights harmonic-band accuracy).
- Early stop on val ESR, patience=10. Target val ESR ≤ 0.02 (≈ −17 dB) → translates to ~−25 dB plugin null.
- TensorBoard: train/val ESR + MSE; render 5 s pred-vs-target WAV every 5 epochs.

#### 4.2.4 Export (`export.py`, `verify_roundtrip.py`)
- Emit `weights/ba283_gru32.json` (rtneural-rs schema: GRU(2→32) + Dense(32→1)).
- Companion `weights/ba283_gru32.meta.json`: `sample_rate=96000`, `input_scale=2.0`, `bias_range=[0.0, 1.0]`, `train_commit=<rev>`, `val_esr`, `hidden=32`.
- **Round-trip test**: 1000 synthetic samples through PyTorch vs rtneural-rs CLI. Assert `max(|diff|) < 1e-5`. Fails loud — Phase 3 is wasted otherwise.

### 4.3 Plugin (`plugin/`)

#### 4.3.1 Crate layout
```
plugin/
  Cargo.toml
  src/
    lib.rs          (Plugin trait impl, params, process loop, dry delay)
    model.rs        (rtneural-rs GRU wrapper)
    oversample.rs   (2× polyphase FIR)
    smoother.rs     (if extending nih_plug smoothers)
  weights/
    ba283_gru32.json
  xtask/
    bundle.rs
```

#### 4.3.2 Dependencies
- `nih_plug` (git, features = `["vst3"]`)
- `rtneural-rs` (latest stable)
- `serde_json`, `atomic_float`
- Release profile: `lto = "fat"`, `codegen-units = 1`, `opt-level = 3`, `panic = "abort"`.
- Build target: `x86_64-v3` only.

#### 4.3.3 Parameters
| Param | Range | Default | Smoother | Unit |
|-------|-------|---------|----------|------|
| `drive_db`  | −12 to +24 dB | 0   | 20 ms | dB |
| `bias`      | 0.0 to 1.0    | 0.5 | 50 ms | —  |
| `output_db` | −24 to +12 dB | 0   | 20 ms | dB |
| `mix`       | 0 to 100 %    | 100 | 20 ms | %  |

#### 4.3.4 Model wrapper (`model.rs`)
- Compile-time `ModelT<f32, 2, 1, (GRULayerT<f32, 2, 32>, DenseT<f32, 32, 1>)>` — zero heap, fully inlined, SIMD-vectorized by LLVM.
- `models: [BA283Model; 2]` on plugin struct (dual mono, shared weights, independent hidden state).
- Weights baked via `include_str!`. JSON parsed once in `initialize`.
- `reset()` zeros both hidden states.
- No `Mutex`, no `RefCell`, no `Arc` around models.
- Static assert: `BA283Plugin: Send + Sync`.

#### 4.3.5 Oversampling (`oversample.rs`)
- 2× polyphase FIR. 31-tap windowed-sinc Kaiser β=8.6, stopband ≥ 80 dB at Nyquist.
- Coefficients computed offline (`scipy.signal.firwin`), pasted as `const COEFFS: [f32; 31]`.
- Per-channel state: `delay: [f32; 31]` ring + index.
- API: `upsample(x) -> (f32, f32)`, `downsample(y0, y1) -> f32`. Zero alloc.
- Bypassed when host SR ≥ 96 kHz.
- Reported latency: **8 samples** when host SR < 96 kHz, **0** when ≥ 96 kHz.

#### 4.3.6 Process block (`lib.rs`)
```rust
fn process(&mut self, buffer: &mut Buffer, _aux: &mut AuxiliaryBuffers,
           _ctx: &mut impl ProcessContext<Self>) -> ProcessStatus {
    for mut frame in buffer.iter_samples() {
        let drive = db_to_gain(self.params.drive_db.smoothed.next());
        let bias  = self.params.bias.smoothed.next();
        let out_g = db_to_gain(self.params.output_db.smoothed.next());
        let mix   = self.params.mix.smoothed.next() * 0.01;

        for (ch, sample) in frame.iter_mut().enumerate() {
            let dry = *sample;
            let driven = dry * drive;

            let wet = if self.host_sr_ge_96k {
                self.models[ch].forward(&[driven, bias])[0] * out_g
            } else {
                let (u0, u1) = self.os[ch].upsample(driven);
                let w0 = self.models[ch].forward(&[u0, bias])[0];
                let w1 = self.models[ch].forward(&[u1, bias])[0];
                self.os[ch].downsample(w0, w1) * out_g
            };

            let dry_aligned = self.dry_delay[ch].push_pop(dry);
            *sample = wet * mix + dry_aligned * (1.0 - mix);
        }
    }
    ProcessStatus::Normal
}
```

**Hard real-time constraints (CI-enforced via `assert_no_alloc`)**:
- No `Vec::new`, `Box::new`, `String::new`, `format!`, `collect`, `HashMap`.
- No `Mutex`, `RwLock`, `parking_lot::*`.
- No `unwrap()`. Use `unwrap_or(0.0)`.
- No `println!`, `log::*`. `nih_log!` only in non-RT paths.
- `panic = "abort"` so accidental panic kills process rather than poisoning the audio thread.

#### 4.3.7 CPU budget
- GRU(32) ≈ 3.3 k MACs/inference.
- 2 inferences (OS) × 2 channels × 48 kHz host = 384 k inferences/s × 3.3 k = ~1.3 GMAC/s.
- AVX2 core ≈ 30 GMAC/s peak → ~4% per core. Comfortable.

## 5. Risks & Mitigations

| Risk | Mitigation |
|------|------------|
| ngspice non-convergence on transformer/saturation transients | Per-run try/except; `failed.csv` records skips; relax `RELTOL` to 1e-3 on retry; fall back to `trapezoidal` method if `gear` stalls. |
| Interpolated-bias null too shallow (model didn't learn the conditioning manifold smoothly) | Add 4 more bias training points (9 total: every 0.125); retrain. Fallback: bump hidden to 48 (still RT-safe at ~6% CPU per core). |
| rtneural-rs schema drift between Python helper and Rust loader | Mandatory round-trip test (`verify_roundtrip.py`) at end of Task 2.4 — Phase 3 cannot start until passes. |
| rtneural-rs lacks Python export helper at impl time | Hand-roll JSON from `state_dict`. Layout documented in rtneural-rs source. |
| Heap alloc creeps into process block via dependency update | `assert_no_alloc` guard with `#[cfg(debug_assertions)]` macro; CI runs debug build of `verify_realtime.py`. |
| Mix knob causes audible comb filtering due to dry/wet phase mismatch | Dry delay sized to `latency_samples()`. Test at mix=50% with white noise — null any 100 Hz–10 kHz peak/notch > 2 dB. |
| User runs at 88.2 / 176.4 / 192 kHz | At ≥96 kHz, OS bypassed; model runs at host SR directly. Harmonic match degrades gracefully; document. |
| TR3 = 2N3055 ahistorical for BA283 | Comment flag in netlist; provide `build_netlist_bc184_output(bias)` variant for A/B comparison if subjective character is off. |
| ngspice XSPICE core (PWL B-H) ≠ true Jiles-Atherton; B-H curve + turns are plausible defaults, not calibrated to a measured LO1166 | Acceptable for v1: validation is null-vs-SPICE so the dataset is self-consistent. If saturation character is audibly wrong, calibrate B_array/H_array/num_turns from a measured transformer or swap to a B-source hysteresis subcircuit. Defer to v2. |

## 6. Phase Order & Gating

```
Phase 1 (data gen)
   │ gate: 60 wet WAVs render without convergence failures > 5%
   ▼
Phase 2 (training)
   │ gate: val ESR ≤ 0.02 AND round-trip test < 1e-5
   ▼
Phase 3 (plugin)
   │ gate: cargo build --release succeeds + standalone CLI renders an impulse
   ▼
Phase 4 (validation)
   │ gate: all numerical pass gates green
   ▼
Manual DAW null test → SHIP
```

Do not advance through a gate. If gate fails, return to the previous phase.

> ```python
> def pre_emphasis(x, alpha=0.85):
>     return x[:, 1:, :] - alpha * x[:, :-1, :]
> def esr(p, t):
>     return ((p - t) ** 2).sum() / ((t ** 2).sum() + 1e-8)
> loss = 0.75 * esr(pre_emphasis(pred), pre_emphasis(target)) + 0.25 * F.mse_loss(pred, target)
> ```
> 5. `Adam(lr=5e-3)` + `CosineAnnealingLR(T_max=epochs)`.
>
> Val ESR every epoch. Early stop patience=10 on val ESR. Save best checkpoint to `checkpoints/best.pth`. TensorBoard log train/val ESR + MSE per epoch; log a 5-second predicted vs target WAV every 5 epochs. CPU-only training is fine.

**Task 2.4 — RTNeural export + round-trip test**
> Write `train/export.py`. Load `checkpoints/best.pth`, format weights into the exact rtneural-rs JSON schema for `GRULayer(in=2, hidden=32)` followed by `Dense(in=32, out=1)`. Use the `rtneural` Python helper if available; otherwise hand-roll the JSON (consult rtneural-rs source for layout: `type`, `activation`, `shape`, `weights` flattened in PyTorch order).
>
> Write `weights/ba283_gru32.json`. Also emit `weights/ba283_gru32.meta.json` with: `sample_rate=96000`, `input_scale=2.0`, `bias_range=[0.0, 1.0]`, `train_commit=<git rev>`, `val_esr=<float>`, `hidden=32`.
>
> Then write `train/verify_roundtrip.py` — render 1000 samples of synthetic test input through PyTorch and via a small Rust CLI (or `rtneural` Python bindings if more convenient at this stage) and assert `max(|diff|) < 1e-5`. Fail loud if mismatch — Phase 3 is wasted otherwise.

### 7.4 Phase 3 — Plugin

**Task 3.1 — Cargo project + params**
> Generate `plugin/Cargo.toml` and `plugin/src/lib.rs` skeleton.
>
> Dependencies: `nih_plug` (git, features = ["vst3"]), `rtneural-rs` (latest), `serde_json`, `atomic_float`.
> Profile.release: `lto = "fat"`, `codegen-units = 1`, `opt-level = 3`, `panic = "abort"`.
> Build target: `x86_64-v3` only. No aarch64.
>
> Define `struct BA283Plugin` and `struct BA283Params` (derive `Params`):
> - `drive_db: FloatParam` range −12 dB to +24 dB, default 0, smoother time 20 ms, unit "dB".
> - `bias: FloatParam` range 0.0 to 1.0, default 0.5, smoother time 50 ms.
> - `output_db: FloatParam` range −24 dB to +12 dB, default 0, smoother time 20 ms, unit "dB".
> - `mix: FloatParam` range 0.0 to 100.0, default 100.0, smoother time 20 ms, unit "%".
>
> Implement `Plugin` trait with stub `initialize`, `reset`, `process` returning `ProcessStatus::Normal`. AudioIOLayout: dual-mono in/out (2 ch in, 2 ch out, also mono-compatible). Provide `nih_export_vst3!`.

**Task 3.2 — Model state instantiation**
> Write `plugin/src/model.rs`. Embed weights via:
> ```rust
> const WEIGHTS_JSON: &str = include_str!("../weights/ba283_gru32.json");
> ```
> Define `type BA283Model = ModelT<f32, 2, 1, (GRULayerT<f32, 2, 32>, DenseT<f32, 32, 1>)>;` (verify exact rtneural-rs generic syntax).
>
> Plugin struct holds `models: [BA283Model; 2]` (dual mono). In `initialize(...)`: parse `WEIGHTS_JSON` once, call `model.load_from_json(...)` on both instances. In `reset(...)`: call `model.reset()` on both to zero hidden state. No `Mutex`, no `RefCell`, no `Arc` around models — nih_plug guarantees single-threaded process access.
>
> Confirm `BA283Plugin: Send + Sync`. Add a static assertion: `const _: fn() = || { fn assert_send_sync<T: Send + Sync>() {} assert_send_sync::<BA283Plugin>(); };`.

**Task 3.3 — Oversampling**
> Write `plugin/src/oversample.rs`. Implement `Oversample2x` per channel:
> - 31-tap windowed-sinc Kaiser β=8.6 lowpass, cutoff 0.5 of upsampled Nyquist (i.e. host Nyquist), stopband ≥ 80 dB. Compute coefficients offline (Python `scipy.signal.firwin` or numpy), paste as `const COEFFS: [f32; 31]`.
> - Two-phase polyphase decomposition: `COEFFS_E: [f32; 16]`, `COEFFS_O: [f32; 15]` (or pad to 16 — document layout).
> - State: `delay: [f32; 31]` ring buffer, `idx: usize`.
> - API: `fn upsample(&mut self, x: f32) -> (f32, f32)` returns two upsampled samples; `fn downsample(&mut self, y0: f32, y1: f32) -> f32`.
> - Zero alloc. No `Vec`.
>
> Report `latency_samples()` from plugin = 8 when host SR < 96 kHz (round up of FIR group delay), 0 when host SR ≥ 96 kHz.

**Task 3.4 — Process block**
> Implement `process` in `plugin/src/lib.rs` per the body shown in Section 4.3.6 of the design. Strict rules:
> - Zero heap allocation. No `Vec::new`, `Box::new`, `String::new`, `format!`, `to_string`, `collect`, `HashMap`, `BTreeMap`.
> - No locks: `Mutex`, `RwLock`, `parking_lot::*`, `std::sync::*` are banned from the process block.
> - No `unwrap()`. Use `unwrap_or` with sensible default (0.0 for audio).
> - No I/O, no logging.
> - When host SR ≥ 96 kHz, bypass `Oversample2x` and run one inference per sample.
> - Mix logic uses an 8-sample (or `latency_samples()`-sized) `[f32; 16]` ring delay on the dry path to keep dry/wet phase-coherent at non-100% mix.
>
> Wrap the file with a `#[cfg(debug_assertions)] use assert_no_alloc::*;` and an `assert_no_alloc!` guard around the inner per-sample logic to catch regressions in CI.

### 7.5 Phase 4 — Validation

**Task 4.1 — Headless numerical null test**
> Write `tests/verify_numerical.py`. Build the plugin's standalone CLI target (`cargo build --release --bin ba283_standalone --target x86_64-unknown-linux-gnu`) which renders an input WAV through the plugin to an output WAV with `--bias`, `--drive-db`, `--output-db`, `--mix` flags.
>
> For each of 3 held-out test stimuli at bias=0.5, drive=0, output=0, mix=100:
> 1. Render via SPICE → `wet_spice.wav`.
> 2. Render via plugin standalone → `wet_plugin.wav`.
> 3. Cross-correlate first 2 s, snap to integer sample offset.
> 4. Compute and print:
>    - Broadband `20 * log10(rms(null) / rms(spice))` — must be ≤ −22 dB pass (target −25).
>    - Per-octave null via STFT, 1/3-octave bands 50 Hz–15 kHz — flag any band > −15 dB.
>    - `max(|null|)` — flag if > 0.05.
> 5. Exit 0 on pass-all, exit 1 otherwise.

**Task 4.2 — Bias-sweep coverage test**
> Write `tests/verify_bias_sweep.py`. Same stimulus set. For `bias ∈ [0.0, 0.125, 0.25, 0.375, 0.5, 0.625, 0.75, 0.875, 1.0]`: render plugin + SPICE at matching bias, compute null. Trained-point bias values must null ≤ −22 dB. Interpolated points (0.125, 0.375, 0.625, 0.875) must null ≤ −18 dB. Print a table and exit non-zero on any failure.

**Task 4.3 — Realtime safety & latency**
> Write `tests/verify_realtime.py`. Build with `assert_no_alloc` enabled. Process 60 s of audio through plugin standalone, assert zero heap allocations from inside `process`. Process an impulse and assert observed peak position matches plugin-reported `latency_samples()`. Process a loud burst → call `reset()` via standalone CLI → process silence; assert output decays to `|x| < 1e-5` within 100 samples.
>
> Separately, write `tests/verify_xrun.sh`: run plugin on `chrt -f 85` realtime thread (Linux) with 64-sample buffer @ 48 kHz for 10 minutes, capture per-callback timing via plugin-internal `Instant` measurement printed to stderr (only allowed because it's a non-shipping test build). Worst-case callback time must stay under 333 µs.

**Task 4.4 — Ableton Live null test protocol**
> Document `docs/null_test_ableton.md`:
> 1. New Live session, 96 kHz internal SR preferred (set host = train SR → plugin latency = 0). If 48 kHz, plugin reports 8-sample latency.
> 2. Track 1 "PLUGIN": import dry test WAV → insert BA283 VST3 (bias 0.5, drive 0 dB, output 0 dB, mix 100%). Track Delay = 0 samples.
> 3. Track 2 "SPICE": import the static `wet_spice.wav` rendered in Task 4.1. Track Delay = +8 samples if host=48k, 0 if host=96k.
> 4. Insert Live `Utility` on Track 2, enable phase invert (Ø).
> 5. Both tracks routed to a return bus "NULL" (sends only, master = -∞). Insert SPAN on the NULL bus.
> 6. Play. Expect broadband residual ≤ −25 dB, no octave > −15 dB.
> 7. If residual contains coherent musical content (you can hum along) → model failed; rerun Task 4.1 numerically before assuming DAW config error.
>
> Include screenshots placeholder paths.

**Task 4.5 — Regression suite**
> Write `tests/regression/run.sh`. Render the 3 held-out stimuli through the current plugin build, byte-compare (tolerance 1e-5 per sample) against committed reference WAVs in `tests/regression/refs/` (stored via Git LFS). Exit non-zero on mismatch. Wire into CI as a blocking job for any PR touching `plugin/src/`, `weights/`, or `Cargo.lock`.
